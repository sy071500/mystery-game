# 설계 문서 — 웹 조사형 추리 게임

> 상태: 초안 v0.3 · 작성일 2026-11-09

## 1. 개요

| 항목 | 내용 |
|---|---|
| 장르 | 조사형 추리 (단서 수집 → 심문 → 지목) |
| 플랫폼 | 웹 브라우저 (HTML/CSS/JavaScript, 빌드 도구 없음) |
| 배포 | GitHub Pages |
| 규모 | 고정 시나리오 단편 1편, 플레이타임 30~45분 |
| 핵심 재미 | "내가 직접 알아냈다"는 감각. 정답을 맞히는 데 그치지 않고 **근거를 제시해** 증명하는 것 |

### 디자인 원칙
1. **공정성**: 정답에 필요한 단서는 모두 게임 안에서 얻을 수 있다. 운이나 숨은 픽셀 찾기는 없다.
2. **추론은 플레이어가 한다**: 게임이 "A와 B를 조합하면 C다"라고 대신 말해 주지 않는다.
3. **근거 기반 판정**: 범인 지목만으로는 부족하고, 왜 그런지 증거로 뒷받침해야 한다.
4. **데이터 주도**: 사건 내용은 전부 JSON에 넣고, 엔진 코드는 사건 내용을 몰라도 돌아가게 한다. 그래야 나중에 사건을 추가하기 쉽다.

## 2. 핵심 게임 루프

```
[사건 브리핑] → ┌─ [장소 조사] → 단서 획득 ─┐
                │                           ├→ [수첩 정리] ─→ [추리쇼: 반론 격파 → 범인 지목] → [자백/엔딩]
                └─ [용의자 심문] ← 단서 제시 ┘
```

1. **브리핑**: 사건 개요, 피해자, 용의자 소개
2. **조사**: 장소를 선택하고 오브젝트를 클릭해 단서를 얻는다
3. **심문**: 용의자에게 주제나 단서를 제시하면 새 진술이 열린다 (진술 자체도 단서가 된다)
4. **수첩**: 얻은 단서, 진술, 타임라인을 자동으로 기록하고 플레이어가 메모할 수 있다
5. **추리쇼**: 관계자의 반론을 증거로 무너뜨리고, 범인을 직접 지목한다
6. **엔딩**: 범인의 자백, 진상 요약, 등급

### 시간 제한 없음
- 시간과 행동 횟수에 제한을 두지 않는다. 플레이어는 원하는 만큼 조사하고 심문할 수 있다
- 대신 **추리쇼**가 긴장의 정점이다 (→ 3.4)
- 막혔을 때를 위한 장치: **조수의 혼잣말 힌트**. 새 단서를 얻지 못한 채 일정 횟수를 행동하면, 조수가 아직 확인하지 않은 장소나 인물을 은근히 언급한다. 정답을 직접 말하지는 않는다

### 톤과 분위기 — 소년탐정 추리 만화풍
- 현대 배경, 고립된 장소(산장, 별장, 열차, 섬)
- **사건마다 트릭 하나**: 알리바이 트릭, 밀실 트릭, 사망 시각 조작 등
- 처음엔 배경처럼 지나쳤던 단서 하나가 모든 걸 뒤집는 "결정적 단서"
- 피날레는 관계자를 한자리에 모아 놓고 펼치는 **추리쇼**
- 범인에게는 과거의 악연에서 나온, 비극적이지만 이해할 수 있는 동기가 있다
- 기존 작품의 이름, 캐릭터, 설정은 가져오지 않는다. 장르의 느낌만 빌려 온다

## 3. 시스템 설계

### 3.1 단서 (Clue)
- 종류: `물증`, `진술`, `기록`(문서·사진), `관찰`(현장 상태)
- 단서에는 **태그**가 붙고, 태그는 추리 판정과 심문 반응에 쓰인다
- 일부 단서는 **조건부**로 등장한다 (예: 열쇠를 얻어야 서랍이 열림, 특정 진술을 들어야 장소가 열림)

### 3.2 심문 (Interrogation)
- 용의자마다 기본 대화 주제가 있다
- **단서 제시**: 수첩의 단서를 들이밀면 반응이 나온다
  - 관련 있는 단서 → 새 진술이나 거짓말 탄로
  - 관련 없는 단서 → 공통 반응 ("그게 저랑 무슨 상관이죠?")
- 각 용의자는 **비밀**을 하나씩 갖고 있다. 범인이 아니어도 무언가를 숨긴다 → 미끼(레드 헤링) 역할

### 3.3 수첩 (Notebook)
- 탭 구성: 단서 / 인물 / 타임라인 / 메모
- 타임라인: 진술에서 나온 시각 정보를 자동으로 배치한다. 서로 어긋나는 진술은 나란히 보여 줄 뿐, **모순이라고 표시하지는 않는다** (판단은 플레이어 몫)

### 3.4 추리쇼 — 범인을 찾는 피날레
단서를 충분히 모았다고 판단하면 플레이어가 **추리쇼를 시작**한다. 관계자를 모두 거실에 모아 놓고, 플레이어가 직접 추리를 증명해 나간다. 따로 답안을 제출하는 화면은 없다.

**진행 방식**
1. **반론 → 증거 제시**: 관계자가 반론하면 ("사고잖아요!", "22:30에 목소리를 들었잖습니까") 플레이어가 수첩에서 증거 하나를 골라 제시한다
   - 맞는 증거: 탐정의 결정타 대사 + 증거 카드가 꽂히며 "증명" 도장 → 다음 단계
   - 틀린 증거: 상대가 다시 반박하고 **추리력**이 1 깎인다. 같은 단계를 다시 시도한다
2. **범인 지목**: 사망 시각과 트릭을 밝힌 뒤, 관계자 중 한 명을 범인으로 지목한다
   - 틀리게 지목하면 그 인물이 알리바이로 반박한다 ("잘못된 지목", 추리력 −1). 다시 지목한다
3. **범인 몰아붙이기**: 지목된 범인이 거짓 진술과 반론으로 버틴다. 알리바이 → 흉기 → 동기 순서로 증거를 들이밀어 무너뜨린다
4. **자백 → 사건 종결**: 범인의 고백, 진상 요약, 등급

**추리력 (실패 조건)**
- 5에서 시작한다. 틀린 증거나 틀린 지목마다 1씩 줄어든다
- 0이 되면 "범인이 빠져나갔다" 엔딩으로 간다. 처음부터 다시 도전할 수 있고, 모아 둔 단서는 유지된다

**등급**
- 남은 추리력 5 → S, 4 → A, 3 → B, 2 이하 → C

**데이터**
- 사건 JSON의 `finale.steps`에 단계를 순서대로 정의한다
- 단계 종류: `say` (탐정 대사) / `evidence` (반론 + 정답 증거 목록) / `accuse` (범인 지목) / `confess` (자백)
- `evidence` 단계에는 `who` (반론하는 인물), `line` (반론), `ok` (정답 증거 ID 목록), `punch`/`text` (성공 대사), `no` (틀렸을 때 반박)를 둔다
- 수첩에 없는 증거는 제시할 수 없다. 그래서 조사가 부족하면 추리쇼 도중 막힌다. 이때는 추리쇼에서 나가 조사를 더 할 수 있다

## 4. 데이터 구조 (JSON)

사건 하나는 `data/cases/<case-id>.json` 파일 하나다.

```jsonc
{
  "id": "case01",
  "title": "사건 제목",
  "briefing": "사건 개요 텍스트",

  "solution": {
    "culprit": "suspect_b",
    "method": "method_poison",
    "motive": "motive_debt"
  },

  "suspects": [
    {
      "id": "suspect_b",
      "name": "이름",
      "role": "피해자와의 관계",
      "secret": "숨기고 있는 것 (설계용 메모, 플레이어에게는 노출 안 함)",
      "topics": [
        { "id": "alibi", "label": "그날 밤 행적", "statementClue": "st_b_alibi" }
      ],
      "reactions": [
        { "clue": "clue_receipt", "statementClue": "st_b_lie_exposed" }
      ],
      "defaultReaction": "그게 저랑 무슨 상관이죠?"
    }
  ],

  "locations": [
    {
      "id": "study",
      "name": "서재",
      "unlockedBy": null,
      "objects": [
        { "id": "desk", "label": "책상", "clue": "clue_receipt", "requires": null }
      ]
    }
  ],

  "clues": [
    {
      "id": "clue_receipt",
      "type": "기록",
      "name": "약국 영수증",
      "description": "…",
      "tags": ["poison", "suspect_b"],
      "time": "21:30"
    }
  ],

  "options": {
    "method": [{ "id": "method_poison", "label": "독살" }],
    "motive": [{ "id": "motive_debt", "label": "빚" }]
  },

  "evidence": {
    "culprit": { "key": ["clue_receipt"], "support": ["st_b_lie_exposed"], "herring": ["clue_x"] },
    "method":  { "key": [], "support": [], "herring": [] },
    "motive":  { "key": [], "support": [], "herring": [] }
  },

  "finale": {
    "steps": [
      { "type": "say", "punch": "범인은 이 안에 있습니다.", "text": "…" },
      { "type": "evidence", "who": "suspect_a", "line": "사고잖아요!", "ok": ["clue_x"],
        "punch": "이건 사고가 아닙니다!", "text": "…", "no": "그게 무슨 증거죠?" },
      { "type": "accuse", "ok": "suspect_b", "wrong": { "suspect_a": "알리바이 반박 대사" } },
      { "type": "confess", "who": "suspect_b", "line": "…" }
    ]
  }
}
```

### 검증 스크립트 (`tools/validate-case.js`)
사건을 쓸 때 실수를 막아 준다. Node로 실행한다.
- 존재하지 않는 ID를 참조하지 않는지
- **도달 가능성**: 시작 상태에서 조건(`requires`, `unlockedBy`)을 따라가 모든 `key` 단서를 얻을 수 있는지
- 추리쇼의 각 단계가 실제로 획득 가능한 단서만 요구하는지
- 질문마다 `key` 단서가 2개 이상인지 (단서 하나에만 의존하지 않도록)

## 6. 기술 구조

```
mystery-game/
├── index.html
├── src/
│   ├── main.js          # 부트스트랩, 화면 전환
│   ├── state.js         # 게임 상태 (획득 단서, 플래그) + localStorage 저장
│   ├── engine.js        # 조사/심문/조건 해석 로직 (사건 데이터와 무관)
│   ├── scoring.js       # 최종 추리 채점
│   └── ui/              # 화면별 렌더링 (location, interrogation, notebook, accusation)
├── data/cases/case01.json
├── tools/validate-case.js
├── docs/DESIGN.md       # 이 문서
└── docs/CASE01.md       # 사건 1의 진상, 타임라인, 단서 맵 (스포일러)
```
- 프레임워크 없이 순수 JS(ES Modules)로 작성한다
- 상태는 단일 객체로 두고, 변경할 때마다 다시 렌더링한다 (규모가 작아서 이 방식으로 충분)
- 세이브는 `localStorage`. 실패해도 게임은 계속 진행된다

## 7. 사건 시나리오 작성 절차

시나리오는 **진상부터 거꾸로** 만든다.

1. **진상 확정**: 범인, 수단, 동기, 분 단위 실제 타임라인
2. **용의자 설계**: 3~4명. 저마다 범행 기회 하나와 숨기는 비밀 하나를 준다
3. **흔적 배치**: 진상이 남긴 물리적·기록상 흔적 → 핵심 단서
4. **거짓말 설계**: 범인의 거짓 진술 1~2개 + 그 거짓을 깨뜨리는 단서
5. **미끼 배치**: 다른 용의자의 비밀이 만들어 내는 의심스러운 흔적
6. **잠금 구조**: 단서 사이의 선후 관계 (3단계 이하로 유지)
7. **검증**: `validate-case.js` 실행 + 처음 하는 사람에게 플레이 테스트
